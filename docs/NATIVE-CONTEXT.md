# 2.3.8：上游水位、压缩预算和原生圆环

没有常驻浮条，也不需要长等待启动器。正式 PI 0.22.0 + 此插件即可在本网关一次成功响应后运行 `/acp-context`；它按需弹出一条结果，不向模型发送消息。需要像 2.3.7 一样批准 `agent.extension`。不批准时网关仍工作，但不会加载此命令或提供扩展读数。

| 数据 | 来源 | 用途 |
|---|---|---|
| 单次请求的 input / output / cache / reasoning | 可确认属于一个未拆分请求的上游正式用量 | 标准 OpenAI usage；由 PI 自己记账/校准。工具链只提供整轮总账等无法归属时不补造分项。 |
| 本 HTTP 步最近的原始占用 / 可选窗口 | ACP `usage_update.used` / `size` | 仅观测，可以回落、可以明确为 0；不包括重发推测增量。未知不是 0。不是计费量，也不意味着 PI 能安全使用上游整个窗口。 |
| PI 输入估算 / 硬限额 | PI 运行时计算，包括历史、系统提示和声明的工具，预留输出空间 | PI 判断压缩的口径；不等于 ACP 水位。只读，不改变阈值和故障保护。 |

网关给本次模型 HTTP 响应加 `x-antigravity-acp-context-id`。PI 扩展仅向本机已确认的同一网关读这个短期回执，不带鉴权头、cookie、提示词或对话内容，不跟随重定向；不保存回执或读数到会话文件。上游未报告则显示未知；本地桥接的估算、`acp_turn_usage` 合计不能冒充原始水位。标准 usage 与诊断字段分开，详见 [USAGE-MAPPING](USAGE-MAPPING.md)。

ACP 的水位事件按会话发出，不含底层每次模型调用的独立 ID。这里的“本步实测”是网关在当前有效请求期间收到的最新可归属水位，不是独立 tokenizer 对待发提示词的逐 token 测量；上游不标明内部调用时无法进一步拆分。结束的请求不接纳迟到更新。回执最多 512 项，10 分钟过期，重启即失效；相同请求已读到的最近样本只留在当前 PI 运行时的内存里。

工具回填以完整结果实际交还给本地 ACP 工具桥为界，不以宿主发起下一次 HTTP 请求为界；协议不提供每条通知的底层派发 ID。若某次派发失败、取消或超时，之后在同一 ACP 连接上复用该会话 ID 时，旧派发的迟报与新派发的实测不可区分。该 ID 后续不再发布无标签水位，不只是跳过一条通知。若既有恢复流程自然使用新的会话 ID 或重建传输，可以再次采样；不会为取数改会话、额外发请求或让用户重启。已拒绝、失效或未报告不是零。

**2.3.9（原版 PI，无补丁）：** 也可在官方输入框插槽自动显示独立读数。它不会写入或替换本节所说的 PI 原生圆环。见[工具栏读数](CONTEXT-METER.md)。

宿主侧也要配对请求。原版 0.22.0 在同一运行时有多个未配对的响应头，插件不按回调抵达次序猜测，这批显示未知。若中止/报错的请求根本没有响应头，2.3.9 在终态撤销等待，用回环诊断 GET 返回的回执签发时间核实之后的独立请求。旧回执、时间打平或不能核实的一律不认领。时间信息不进模型请求或模型回包。可选宿主桥另有本地请求编号。两种方式都不改模型 payload。

**旧版 `/acp-context` 和可选原生菜单的区别：** 命令的“压缩前采样”来自扩展事件当时可读的会话状态。正式 0.22.0 不对扩展报告尚未加入历史的待发消息，也不公开是否启用了自动压缩；命令不会猜阈值。带适配的原生菜单记录判定时实际传入的预算，能包含待发消息或工具结果；菜单会区分阈值触发、模型请求、手动压缩等原因。

**原生菜单。** 原版 0.22.0 没有原生占用写入口。只装插件不会劫持 DOM、修改 asar、重写会话或模型绑定来强行改变圆环。独立发布的、基于官方 `v0.22.0` 的可选源码适配把同一圆环接到运行时预算：主显示使用硬输入预算而非整个模型窗口，菜单分列自动线、最近压缩前预算、模型窗口和上游实测。没有活动源时退回 PI 原行为。本地读数和上次压缩快照不是永久历史；重建运行时后需要重新确认。请勿将宿主源码补丁当插件导入。

例如模型窗口 256,000，输出预留 32,000，硬输入限额 224,000，正式 0.22.0 默认自动线 201,600。预算 131,752 对应已用约 59%；38,655 / 256,000 是另一个口径的约 15%。其他绑定及关闭自动压缩的情况以宿主实际值为准。
