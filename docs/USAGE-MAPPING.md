# 2.3.6：插件 usage 映射修复

**2.3.8 增补（不改下面的标准用量规则）：** 两种 API 流式和非流式响应均可提供本次 HTTP 请求的 `x-antigravity-acp-context-id`。可归属的原始 `usage_update` 单独映射到 `usage.acp_context = {source:"acp.usage_update", used, size?}` 和回执；`used` 必须是非负安全整数（允许真实回落及 0），`size` 只取同一条通知里的正安全整数。无可靠水位则不返回此字段。它不是 `context_used`、不是请求输入，也不是整轮累计。如何在 PI 查询，见 [云端实测与原生压缩预算](NATIVE-CONTEXT.md)。

## 修复范围

仅修改插件，不要求修改 PI-Desktop、更新宿主、开启 continuation 协议或更换模型绑定。基于已发布的 2.3.5 源码隔离修复，不包含另一个需要宿主配合的 managed-continuation 方案。

- ACP `usage_update.used` 是上下文占用，可能已包含输出，也可能延迟到工具回填后或合并多个模型调用。它不是本次输入。
- ACP 1.5.0 的 `PromptResponse.usage` 是整个 `session/prompt` 的主轨迹累计分项，不是最后一次 HTTP 工具步的分项。该版本没有暴露可靠的 per-leg 明细。
- 旧映射把占用写进标准输入，再报告输出；还把累计缓存按比例分摊、累计输出减去此前的可见输出估计。这些处理会制造不匹配的宿主校准样本。

## 新映射合同

Chat 与 Responses 使用同一映射规则：

| 情况 | 标准 input / output / total / cache / reasoning | 诊断数据 |
| --- | --- | --- |
| 完整、未拆分的单次 ACP prompt 终态，未观察到工具、挂起、多次不同水位或重试；若有水位必须与终态 total 一致 | `input = uncached input + cached read + cached write`，输出直接使用官方 output（已含 thought），total 必须与分项自洽 | `usage_status: measured` |
| 工具挂起、拆分后的终态、多 prompt 催答、不完整／不自洽计数、取消、无法确认作用域 | **省略全部标准计数字段**，不是填 0；不把可见输出估计当官方计数 | `usage_status: unavailable` |

- `context_used` / `context_size` 保留旧有上下文诊断口径；其中可能有桥接增量估算或累计值展开，不能当精确输入或计费量。原始水位见 `[acp-diag].rawUsed`。
- `observed_output_tokens` / `observed_reasoning_tokens` 仅是当前桥接步骤累计观察到的正文、思考及工具参数的本地估计；`output_estimated` 不会使它们变成官方计数。
- `acp_turn_usage` 保存可用的官方 prompt 汇总及 `scope: prompt_aggregate`、`prompt_count`。多次催答对共同存在的计数字段求和，不再取最后一次输入。缺失、非法值与显式零分开处理；ACP 自身可能把未知 cache-write 折为零，因此不据此声称已确认零缓存写入。
- 不减去估计输出来倒推 `used`，不缩放／伪造逐步缓存，不把整轮累计输出结算到最后一步。
- 不改 upstream 水位回落、会话复用、工具参数／结果、取消、串行化、429 退避、节流设置和模型窗口通告。
- 修复 Chat 工具挂起时再次发送已流出的正文，避免同一段内容重复进入宿主历史；按桥接正文的实际已交付前缀推进游标，失败写入不推进；跨 HTTP 迟到正文保留到合法完整回填后优先补发。碎片流、并行／部分回填、无新正文直接结束和取消／steering 隔离均有回归。

### 现有宿主上的表现

PI-Desktop 忽略自定义诊断字段。没有标准用量时，现有适配器不会提交有效校准样本，宿主使用自己的历史估算与原始请求预算保护；不绕过容量上限。工具链的 token／cache UI 可能显示缺失或 0，**不代表实际用量／缓存命中为零**。真实单步数据上游未提供，不能在插件中凭空补齐。

本地估算可能比普通 API 的实测值高，也可能低；此版修复错误映射，不承诺所有预算数字一致、无限工具链或恢复到固定 500 次工具。旧对话中已保存的错误 usage 或既有校准状态不会被插件偷偷改写，升级后建议用新对话进行同条件验收。

## 离线同条件验证

实际 2.3.5／2.3.6 网关 + mock ACP → 记录代理 → 已构建的现有 DesktopAgentRuntime 与 pi-ai；普通 API 组仅替换相同 SSE 中的标准用量。没有调用真实模型，没有修改或启动已安装宿主。

窗口 256000，输出保留 32000，硬边界 224000，自动压缩阈值 201600。每组请求正文、工具结果、输出内容和原始历史预算逐项断言相同。随机 ID 做一致化；旧 Chat 挂起的重复正文由代理显式识别、计数并移除，**该表隔离 usage 映射收益，不混入正文去重收益**。修复后网关不需此移除操作。

两种 API × 三场景 × 三组，共 18 组：

| 场景（末次决策） | 普通 API 预算 | 2.3.5 预算 | 2.3.6 预算 | 相同原始历史下限 | 压缩请求次数：普通／旧／新 |
| --- | ---: | ---: | ---: | ---: | --- |
| 输入160K、输出24K、再回填24K字符 | 190858 | 214858 | 181943 | 159353 | 0 / 1 / 0 |
| 五步，输出稳定1K | 60143 | 61143 | 61947 | 54357 | 0 / 0 / 0 |
| 输出1K/4K/7K/10K/13K，最后回填40K字符 | 165429 | 206997 | 163661 | 143357 | 0 / 1 / 0 |

增长输出场景旧插件学得 trailing ratio 3.49956，普通组 0.87489；新插件不向校准器提交不可靠样本，保持默认 1。稳定场景显示新预算并非总比旧版小，修复目标是计量口径正确，而非压低数字。

另有精确单次样本：输入100000（含80000 cache）+ 输出32000、水位132000。旧版标准输入132000、total164000；新版标准输入100000、total132000，缓存与思考分项保持真实。

测试拦截 `runCompaction` 并返回 false，只验证**请求压缩的决策**，不是成功生成摘要。真实安装后的长链体验、上游隐藏步骤和所有历史退化原因仍需实测；不把合成工具数量当历史数据包重放。
